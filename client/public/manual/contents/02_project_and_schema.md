# 02. プロジェクト & スキーマ管理

## 1. プロジェクトの作成と保存の仕組み

### 新規プロジェクトの作成
1. ヘッダーの **「📁 ファイル」→「✨ 新規プロジェクト」**（またはプロジェクト未作成時の初期画面にある「新規プロジェクト作成」ボタン）をクリックします。
2. モーダルが開いたら **プロジェクト名**（必須）を入力し、**「追加」** をクリックします。
3. ユーザー専用のワークスペースが初期化され、新しいプロジェクトが作成されます。

> **注意**: 新規プロジェクトを作成すると、それまでワークスペース内にあった旧プロジェクトのスキーマやER図データはクリーンアップされ、新しいプロジェクトに切り替わります。既存プロジェクトをバックアップしておきたい場合は、事前に **「📁 ファイル」→「📤 エクスポート...」→「プロジェクト (ZIP)」** で保存してください。

### 自動差分保存と手動保存
- **自動差分保存**:
  DBML Editor v2.0.0 では、スキーマの追加・インポート、テーブルの追加・編集・削除、テーブルグループやノートの更新、ER図の編集などを行った際、**変更が発生したスキーマやER図のみを自動検知（差分保存）してサーバーへ即座に永続化**します。そのため、大規模プロジェクトでも保存待ちのストレスなく安全に作業を継続できます。
- **手動保存**:
  任意のタイミングで明示的に保存を実行したい場合は、ヘッダーの **「📁 ファイル」→「💾 プロジェクトを保存」** をクリックします。

## 2. プロジェクト設定
ヘッダーの **「📁 ファイル」→「⚙️ プロジェクト設定...」**（または左ツリーの「プロジェクト」セクションの編集アイコン）から、プロジェクト全体の基本情報を設定できます。

| 設定項目 | 説明 |
| :--- | :--- |
| **プロジェクト名** | プロジェクトの名称（仕様書出力やプロジェクトZIP管理に使用されます） |
| **説明 / ノート** | プロジェクトの概要、システム名、設計方針やメモなどを自由に記述できます |

---

## 3. マルチスキーマ管理とスキーマ設定

DBML Editor は、1つのプロジェクト内で複数のデータベーススキーマ（例: マスタ系スキーマ、トランザクション系スキーマ、外部連携スキーマなど）を同時に管理できる **マルチスキーマ構成** に対応しています。

### スキーマの新規追加
1. 左ペイン（オブジェクトツリー）の「スキーマ」見出し横にある **「＋」ボタン** をクリックします。
2. 「新規スキーマ作成」モーダルで以下の項目を設定し、**「保存」** をクリックします。

| 設定項目 | 説明 |
| :--- | :--- |
| **スキーマ名** | スキーマ識別子（半角英数字・アンダースコア等。`.dbml` ファイル名としても使用されます） |
| **DBMS方言** | このスキーマが対象とするデータベース種別（標準DBML、Oracle、PostgreSQL、MySQL、SQL Server、Cloud Spanner 等）を選択します |
| **データ表領域 (Tablespaces)** | （方言プラグイン対応時）テーブル用表領域の候補リストをカンマ区切りまたはタグ入力で登録します |
| **INDEX表領域** | （方言プラグイン対応時）インデックス用表領域の候補リストを登録します |
| **LOB表領域** | （方言プラグイン対応時）CLOB / BLOB 等の LOB カラム用表領域の候補リストを登録します |

> **ポイント**:
> - **DBMS方言** はスキーマ単位で保持されます。スキーマを切り替えると、テーブル編集画面のデータ型候補、物理属性フォーム（表領域や PCTFREE 等）、識別子長・予約語バリデーション、および DDL エクスポートのデフォルト方言が自動的に連動します。
> - DDL インポート時に `TABLESPACE` 指定が含まれていた場合、検出された表領域名は自動的にスキーマ設定の表領域候補リストへ登録されます。

### スキーマの切り替え・設定編集・削除
- **スキーマの切り替え**:
  左ツリーの「スキーマ」配下から対象スキーマをクリックするとアクティブスキーマが切り替わり、下部の「テーブル」「テーブルグループ」「ノート」一覧がそのスキーマの内容に更新されます。
- **スキーマ設定の編集**:
  左ツリーの各スキーマ行にある **「⚙️（編集）」アイコン** をクリックすると、DBMS方言や表領域候補リストをいつでも変更できます。
- **スキーマの削除**:
  左ツリーの各スキーマ行にある **「🗑️（削除）」アイコン** をクリックすると、確認ダイアログの後にそのスキーマを削除できます（最後の1スキーマも削除可能です）。

## 4. DBML 参照（Preview）タブ

ヘッダー中央の **「👁️ DBML参照 (Preview)」** タブをクリックすると、現在選択中のスキーマから自動生成された正規化 DBML コードを CodeMirror 6 エディタ上で確認できます。

- **自動正規化フォーマット**:
  テーブル作成・編集時だけでなく、SQL DDL や Excel 設計書からインポートした直後のスキーマもすべて共通の正規化ルール（`dbml-generator`）で整形された DBML コードとして保持・表示されます。
- **テキスト検索**:
  プレビュー画面内の検索バー（または `Ctrl + F`）を使って、テーブル名・カラム名・論理名・表領域名などを大文字小文字の区別なく高速に検索し、`▲（前へ）` / `▼（次へ）` で一致箇所へジャンプできます。
- **コピー**:
  ツールバーのコピーボタンから、スキーマ全体の DBML テキストをワンクリックでクリップボードへコピーできます。
