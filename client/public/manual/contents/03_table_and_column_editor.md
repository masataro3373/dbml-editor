# 03. テーブル・カラム・制約の設計

## 1. テーブル一覧画面の操作
ヘッダー中央の **「📋 テーブル一覧」** タブ（または左ツリーの「テーブル」見出し）を選択すると、現在アクティブなスキーマ内の全テーブルが一覧表示されます。

- **キーワード検索**: テーブル物理名、テーブル論理名、説明（Note）でリアルタイムに絞り込めます（入力欄右端の `×` ボタンまたは `Esc` キーでクリア）。
- **ヘッダカラーフィルタ**: カラーパレットアイコンから特定の色を選択すると、そのヘッダカラーが設定されたテーブルのみを抽出表示できます。
- **新規テーブル追加**: 右上の **「＋ テーブル追加」** ボタン（または左ツリーの「テーブル」横の `＋` ボタン）をクリックすると、新規テーブル作成画面が開きます。
- **テーブルの参照・編集・削除**:
  - テーブル行をクリックすると **テーブル詳細参照ビュー** が開きます。
  - 行右側の **「✏️ 編集」** ボタンでテーブル編集画面へ直接遷移し、**「🗑️ 削除」** ボタンでテーブルを削除します（削除時は、そのテーブルを参照しているリレーションやテーブルグループ内の参照も自動的にクリーンアップされて保存されます）。

## 2. テーブル基本情報・物理属性の設定
テーブル編集画面の上部では、テーブルの基本情報と RDBMS 固有の物理属性を設定します。

### 基本属性
| 項目 | 説明 |
| :--- | :--- |
| **テーブル物理名** | SQL / DBML 上のテーブル識別子（必須。例: `MST_USERS`） |
| **テーブル論理名** | 日本語名称（例: `ユーザーマスタ`）。`logicalname` 等の方言・拡張プラグイン有効時に入力でき、DBML 上は `Table "名" [logicalName: '...']` として保持されます |
| **ヘッダカラー** | ER図のテーブルカード上部やツリー・一覧のカラーバッジに表示する識別色。プリセットパレットまたはカスタムカラーから選択できます |
| **テーブル備考 (Note)** | テーブルの用途や設計メモ。HTML 仕様書や DDL のテーブルコメント出力にも利用されます |

### 方言別のテーブル物理属性（プラグイン連動）
スキーマの DBMS 方言に応じたプラグイン（例: `oracle-dialect`）が有効な場合、物理属性セクションが表示されます。設定値は DBML 末尾の `Metadata Table "テーブル名" { ... }` ブロックとして標準構文を壊さずに保存されます。

- **Oracle Database (`oracle-dialect`) の主な設定項目**:
  - **データ表領域 (`tablespace`)** / **INDEX表領域 (`index_tablespace`)** / **LOB表領域 (`lob_tablespace`)**: スキーマ設定で登録した表領域候補からのプルダウン選択または直接入力
  - **ストレージ・ブロック属性**: `PCTFREE`, `PCTUSED`, `INITRANS`, `MAXTRANS`, `STORAGE (INITIAL / NEXT)`
  - **オプション**: `LOGGING`（ログ出力有無）、`COMPRESS`（圧縮有無）

## 3. カラム（列）の追加と編集
「カラム定義」セクションでは、テーブルの列を一覧形式で素早く定義・編集できます。

| 項目 | 説明 |
| :--- | :--- |
| **順序移動 (`⠿` / `↑` `↓`)** | 行のドラッグまたは上下ボタンでカラムの定義順を並び替えます |
| **カラム物理名** | カラムの物理識別子（必須。例: `USER_ID`） |
| **カラム論理名** | カラムの日本語名称（例: `ユーザーID`）。インライン属性 `[logicalName: '...']` および SQL の `COMMENT ON COLUMN` に反映されます |
| **データ型 (Base Type)** | `VARCHAR2`, `NUMBER`, `CHAR`, `DATE`, `TIMESTAMP`, `CLOB` 等。選択中の方言に応じた型候補がサジェストされます |
| **サイズ / 桁数 (Length)** | 文字長や全体の桁数（例: `VARCHAR2` の `20`、`NUMBER(9, 0)` の `9`） |
| **精度 / スケール (Scale)** | 小数点以下の桁数（例: `NUMBER(9, 0)` の `0`）。基本型・サイズ・精度は DBML 出力時に `"NUMBER(9, 0)"` や `VARCHAR2(20)` へ自動合成されます |
| **PK（主キー）** | 主キーカラムにチェックします。チェックすると自動的に **NN (Not Null)** も有効になります。複数カラムにチェックすると複合主キーとして扱われます |
| **NN（Not Null）** | `NOT NULL` 制約を付与します |
| **UQ（Unique）** | 単一カラムの `UNIQUE` 制約を付与します |
| **AI（Auto Increment）** | 自動採番属性（`increment`）を付与します |
| **デフォルト値 (Default)** | `DEFAULT` 値（例: `'0'`, `0`, `SYSDATE`, `CURRENT_TIMESTAMP`）。データ型に応じて DBML 出力時にクォートが適切に正規化されます |
| **備考 (Note) / 属性補足** | カラムの説明文（Note）や業務上の補足メモを記録できます |

## 4. インデックス・外部キー (FK)・Check制約の定義

テーブル編集画面の下部タブ（または各セクション）で、インデックスや各種制約を定義できます。

### ① インデックス (Indexes)
- **「＋ インデックス追加」** から、単一または複数カラムを組み合わせた複合インデックスを定義できます。
- **設定項目**:
  - **インデックス名**: 物理インデックス名／主キー制約名（例: `PK_MST_USERS`, `IDX_USERS_EMAIL`）
  - **対象カラム**: チェックボックスまたはタグ選択で構成カラム（複数可）を指定します
  - **種別**: `PK（主キー）`、`UNIQUE（一意インデックス）`、または通常インデックス
  - **インデックス表領域 / 備考**: 方言プラグイン有効時はインデックス個別の表領域（`tablespace`）を指定できます

> **自動正規化**: 主キー（PK）と同一名・同一カラム構成の重複 UNIQUE インデックスは、DDL インポート時および DBML 保存時に自動的に整理され、二重定義を防ぎます。

### ② 外部キー / リレーション (Foreign Keys / Refs)
- **「＋ 外部キー追加」** から、他テーブルへの参照制約（DBML の `Ref`）を定義できます。
- **設定項目**:
  - **制約名**: 外部キー制約名（任意）
  - **自テーブルカラム**: 参照元のカラム（複合FK対応）
  - **参照先テーブル & カラム**: 参照先のテーブルと主キー／ユニークカラム
  - **リレーション多重度**: 多対1（`>`）、1対多（`<`）、1対1（`-`）、多対多（`<>`）
  - **参照整合性アクション**: `ON DELETE` / `ON UPDATE`（`CASCADE`, `SET NULL`, `RESTRICT`, `NO ACTION` 等）

### ③ Check 制約 (Checks)
- **「＋ Check制約追加」** から、カラム値の入力制限式（DBML の `checks` ブロック）を定義できます。
- **設定項目**:
  - **制約名**: 例 `CHK_DEL_FLG`
  - **条件式 (Expression)**: 例 `DEL_FLG IN ('0', '1')`

## 5. 方言バリデーション（識別子長・予約語チェック）
スキーマに設定された DBMS 方言ルールに基づき、テーブル編集画面ではリアルタイムに以下の静的チェックが行われます。

- **最大識別子長チェック**:
  例えば Oracle（11g互換設定時は最大 30 バイト／文字、12cR2以降は 128 バイト）や PostgreSQL（63 バイト）などの上限を超過しているテーブル名・カラム名・インデックス名に警告を表示します。
- **DBMS 予約語チェック**:
  `ORDER`, `USER`, `DATE`, `NUMBER`, `SELECT` など、選択中 DBMS の予約語と衝突する識別子に警告バッジを表示し、DDL 実行時の構文エラーを未然に防ぎます。
