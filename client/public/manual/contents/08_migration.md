# 08. マイグレーションSQL自動生成

## 1. マイグレーションツールの概要
**マイグレーションツール** は、2つのスキーマ（または外部 `.dbml` ファイル）を比較して構造差分を自動解析し、既存データを保護しながら新スキーマへ移行するための SQL スクリプト（`CREATE TABLE`, `DROP TABLE`, `ALTER TABLE`, インデックス再作成、および破壊的変更時のデータ退避・再投入スクリプト）を自動生成する **3ステップウィザード** です。

ヘッダーの **「🛠️ ツール」→「🔄 マイグレーションツール」** から起動します。

---

## 2. Step 1：比較対象スキーマの選択と自動差分検出

1. **比較元（旧スキーマ / Old）の指定**:
   プロジェクト内のスキーマをプルダウンから選択するか、**「ファイル読込」** ボタンから過去の `.dbml` ファイルを読み込みます。
2. **比較先（新スキーマ / New）の指定**:
   比較先となる現在のスキーマをプルダウンから選択します（または `.dbml` ファイルを読み込みます）。
3. **完全自動差分検出 & Side-by-Side コード比較**:
   - 比較元と比較先を選択した瞬間に **自動的に差分計算が実行** され、左右並べて表示された CodeMirror 6 エディタ上に追加・変更・削除箇所が色分けハイライト表示されます。
   - 画面上部の **差分ジャンプナビゲーション（`⏮ 最初` `◀ 前へ` `[ 1 / N ]` `▶ 次へ` `⏭ 最終`）** を使って、変更箇所へワンクリックで移動できます。
4. 確認後、右上の **「Step 2 ➔」** ボタンをクリックします。

---

## 3. Step 2：構造化アラインメント差分確認と出力対象選択

Step 2 では、DBML の記述順序やフォーマット揺れに左右されない **構造化 1 対 1 アラインメント比較** の結果を確認し、SQL 生成対象とオプションを選択します。

### 画面構成と機能
- **テーブル一覧（左ペイン）**:
  - 各テーブルの差分ステータス（`新規追加 (ADD)` / `変更 (MODIFY)` / `削除 (DROP)` / `変更なし (UNCHANGED)`）と移行モードバッジが表示されます。
  - **「☑ 変更のあるテーブルのみ表示」** チェックボックスで、差分が存在するテーブルだけに絞り込めます。
  - SQL を出力したいテーブルにチェックを入れます（デフォルトで差分のある全テーブルが選択されます）。
- **構造化詳細 Diff（右ペイン）**:
  選択したテーブルについて、以下の 4 つの観点で旧定義と新定義が 1 対 1 で対比表示されます。
  1. **カラム差分**: カラム追加・削除、データ型変更、桁数拡大（`SIZE_EXPANDED`）／縮小（`SIZE_REDUCED`）、PK変更、NOT NULL制約の追加／解除、DEFAULT値変更
  2. **インデックス差分**: PK・Unique・通常インデックスの追加／変更／削除、構成カラムやインデックス表領域の変更
  3. **外部キー (FK) 差分**: 参照先テーブル・カラムや `ON DELETE` / `ON UPDATE` 条件の変更
  4. **テーブル物理属性・メタデータ差分**: 論理名（`logicalName`）、備考（`Note`）、表領域（`tablespace`, `index_tablespace`）、物理パラメータ（`pctfree` 等）の変更

### マイグレーションモードの自動判定ロジック
変更内容に応じて、各テーブルに最も安全な移行モードが自動割り当てられます。

| マイグレーションモード | 判定条件 | 生成される SQL の処理内容 |
| :--- | :--- | :--- |
| **`ADD`（新規作成）** | 新スキーマにのみ存在するテーブル | `CREATE TABLE` ＋ インデックス・制約 ＋ `COMMENT ON` |
| **`DROP`（テーブル削除）** | 旧スキーマにのみ存在するテーブル | `DROP TABLE` |
| **`RECREATE_TABLE`（データ移行伴う再作成）** | カラム追加、桁数・精度の縮小、データ型変更、NOT NULL制約の新規追加など、`ALTER` だけでは安全に適用できない変更 | 一時退避テーブル作成 ➔ データ退避 ➔ 旧テーブル削除・新テーブル作成 ➔ データ復元（`INSERT INTO ... SELECT`） ➔ インデックス・制約再付与 ➔ 一時テーブル削除 |
| **`ALTER_INPLACE`（インプレース変更）** | カラム桁数の拡大、NOT NULL解除、DEFAULT値変更、カラム削除など `ALTER TABLE` で直接変更可能なケース | `ALTER TABLE ... MODIFY / DROP COLUMN` 等 |
| **`INDEX_ONLY` / `FK_ONLY` / `ATTR_ONLY`** | カラム変更がなく、インデックス・外部キー・論理名／物理属性のみが変更されたケース | `DROP / CREATE INDEX`、`ALTER TABLE ADD / DROP CONSTRAINT`、`COMMENT ON` 等 |

---

## 4. Step 3：マイグレーションSQLのプレビューと一括出力

Step 2 で出力オプション（対象 DBMS 方言、`COMMENT ON` 出力有無、文字コード `UTF-8` / `Shift_JIS`、改行コード `LF` / `CRLF`）を確認して **「Step 3 ➔」** へ進むと、生成されたマイグレーション SQL が表示されます。

- **ファイル階層ツリー（左ペイン）**:
  - 実行順序ごとに整理された SQL ファイル（特に `oracle-dialect` での `RECREATE_TABLE` 時は、安全に段階実行できるよう **6分割ステップ構成の SQL ファイル群**）がツリー表示されます。
- **SQL プレビュー & 編集（右ペイン）**:
  - CodeMirror 6 エディタ上で生成された SQL を確認・検索できます。
  - 表示言語が `English` の場合は SQL 内の手順ヘッダーや注意事項コメントも自動的に英語で出力されます。
- **保存・ダウンロード**:
  - **単一コピー / 個別保存**: 現在表示中の SQL ファイルをクリップボードにコピー、または単独 `.sql` ファイルとして保存します。
  - **一括 ZIP ダウンロード**: 全対象テーブルの移行スクリプト一式をディレクトリ構成付きの `.zip` ファイルとしてワンクリックでダウンロードできます。
